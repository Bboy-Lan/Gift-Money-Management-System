# 礼金簿反馈服务：传统 CloudBase 环境适配

目标是 `cloud-yunda-d5gxrar1s14b2ee0d`，该环境已有其他应用。不得覆盖现有集合、云函数、身份或全局权限配置。原 `cloud-ynnu` 环境及其数据保留。

## 隔离与权限

- 计划使用专属集合 `lijin_feedback_v1`、`lijin_feedback_replies_v1`、`lijin_feedback_admins_v1`、`lijin_announcements_v1`、`lijin_announcement_drafts_v1`，部署前确认名称没有冲突。
- 集合拒绝客户端直接读写；仅专属云函数使用服务端权限访问。云函数调用范围必须只针对专属函数配置，不改其他函数规则。
- 服务端从 CloudBase 运行时 `auth.getUserInfo()` 取得 UID，不接受客户端提供的用户 ID 或管理员标记。管理员仅按独立集合中明确授权的 UID 判定。匿名身份、邮箱验证码、管理员 UID 登记及函数调用策略需要在共享环境配置，并在执行前确认影响。
- 回复及反馈状态必须在同一数据库事务中提交；删除采用软删除，默认不清除回复。所有接口必须限制输入长度及分页，且禁止泄漏其他用户的反馈。
- 不记录礼金库、姓名、金额、地址、文件路径、会话令牌或验证码。

## 切换前缺口

新目标网关及专属云函数已加入桌面网络允许列表，用户授权后已部署服务并切换客户端。云端运行时和本地 SDK 的事务对象接口不同，适配器兼容两者；真实云端测试通过匿名用户隔离、管理员回复与状态变更、可恢复删除、公告草稿及发布。管理员回复及状态已由独立匿名会话实际接收，测试数据已清理。

SDK 依赖审计在升级 axios 和 lodash.unset 后仍报告 lodash.set 高危告警，引用位于数据库 SDK 的实时监听模块；本实现没有调用实时监听。该静态分析不能替代腾讯云对依赖的修复。安装版跨设备验收及长期计费表现仍需持续核验。

旧环境不可读；不能声称历史反馈、用户身份、管理员会话已经迁移。必须等待原环境可访问后设计、核验身份映射与数据迁移；切换目标的客户端不能假装旧记录已迁移。
